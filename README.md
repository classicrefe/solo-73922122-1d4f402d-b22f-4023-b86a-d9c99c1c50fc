# 公交接驳满意度调查 · 两版均分差值复核页（支持反向问卷批次）

更正后的满意度调查需要估计「更正表均分 − 原表均分」及其抽样波动。本服务提供一个
Flask 网页：上传原表 CSV → 入库（SQLite 原样保留录入原分与发卷批号）→
按批次切换正 / 反向口径 → 按户补录 / 改分 / 移除 →
固定种子的 1000 轮泊松自助 → 展示未加权均分差、有效轮数与轮差值的 2.5% / 97.5% 分位。

## 一键启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

- 数据库落在命名卷 `survey-data`（容器内 `/data/survey.db`），容器重建后数据仍在。
- 生产环境请修改 `docker-compose.yml` 中的 `SECRET_KEY`。
- 本地无 Docker 时：`pip install -r requirements.txt` 后
  `gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 wsgi:app`
  （SQLite + 单进程多线程；每请求独立连接）。

## CSV 格式

UTF-8 文本（允许 BOM），每行 **两列或三列**，全表列数必须一致：

- 两列（旧格式，继续按原方式使用）：`住户号,评分`；
- 三列（新格式）：`住户号,评分,发卷批号`。

规则：

- 住户号：非空、全表唯一；
- 评分：0～10 的整数，即问卷上的**录入原分**；
- 发卷批号：任意非空文本；第三列留空则归入「默认批次」（与两列 CSV 同批）；
- 首行若是表头（第二列不是整数）会自动识别并跳过；空行忽略；
- 任一记录非法则整次上传被拒绝，数据库不做任何改动。

## 反向问卷批次与页面操作

1. **上传原表**：录入原分与批号写入 `original_scores` 后不再被任何功能修改；
   所有批次初始均为**正向（按原分计）**，更正表 `corrected_scores` 初始化为
   完全相同的副本（非人工、跟随批次）。
2. **批次方向切换**（网页第 2 区）：分析员可把指定批次在
   正向（原分）与反向（`10 − 原分`）之间来回切换。
   - 切换**只读写汇总数据**（两张轮次汇总表、按桶汇总 `batch_summary` 与全局
     `meta`），不读取、不改动任何住户明细表；
   - 方向与原表、更正表两套汇总在**同一个 SQLite 事务**内一起生效，任一语句
     失败即整体回滚，页面继续沿用旧口径并提示原因；
   - 人工改分、补录与移除状态在切换时原样保留（见下）。
3. **按户更正**（网页第 3 区）：
   - 人工改分与补录一律直接填写**正向分值**（0～10）；
   - **改成与当前相同的分值也算一次人工改分**：该户从此脱离批次换算，
     进入人工池，后续任何批次切换都不再改变它的分数；
   - 补录新增户同样进入人工池（原表无此户）；移除只作用于更正表；
   - 每次更正只重算该户的 1000 个轮次贡献，其余户数据不读取。
4. **查户**：单户查询仍只读取该户明细，一行展示三档值——
   **录入原分**、按当前批次方向**换算后的原表分**（反向时附 `10 − 原分` 算式）、
   以及**更正分**；并标注批次方向、人工标记与移除状态。
5. **重置更正表**：丢弃全部人工改分、补录与移除，更正表住户重新跟随
   **当前**原表口径（即各批次此刻的方向）重新换算。
6. **估计结果**（网页第 4 区，只读 `meta`、`batch_summary` 与两张轮次汇总表，
   不碰住户明细表）：两表户数与未加权均分、未加权均分差（更正 − 原）、
   有效轮数 / 1000、被跳过轮数、轮差值 2.5% / 97.5% 分位（type-7 线性插值，
   与 numpy 默认定义一致）；无法计算时显示明确原因。

### 数据模型如何支撑上述语义

| 表 | 内容 |
| --- | --- |
| `original_scores` | 户号 + **录入原分** `raw_score` + 批号；上传后只增不改（重新上传时整体替换） |
| `corrected_scores` | 户号 + 分数 + `manual` 标记 + 批号。`manual=0` 行存录入原分并跟随批次方向；`manual=1` 行存正向绝对分值（人工 / 补录），不随切换变化 |
| `batches` | 每个批号一行，`direction`：0 正向 / 1 反向 |
| `orig_rounds` | 每轮 × 每**批次**的权重合计与加权评分合计 |
| `corr_rounds` | 每轮 × 每**桶**（真实批次 + 人工池 `MANUAL_BATCH`）的权重合计与加权评分合计 |
| `batch_summary` | 每表每桶的户数与评分合计；方向切换所需的全部信息都在这里 |
| `meta` | 两表户数、评分合计等标量与 schema 版本 |

- 反向切换时，批次桶每轮满足
  `新 weighted_sum = 10 × weight_total − 旧 weighted_sum`，
  未加权合计满足 `新 score_sum = 10 × 户数 − 旧 score_sum`；
- 人工池是一个永不参与批次换算的独立桶，因此切换天然保留人工分数与移除状态；
- 旧版数据库（v1，无批次概念）首次打开时自动就地迁移：原数据归入默认正向批次，
  旧库中与原表分数不同的更正分识别为人工分、被删除的更正户保持移除状态，
  迁移后分析结果与旧库逐轮一致。

## 自助抽样方法（与需求逐条对应）

- 固定种子（`app/bootstrap.py` 中 `MASTER_SEED = 20261123`），共 **1000 轮**；
- 每轮每户独立抽取均值为 1 的泊松权重 `Pois(1)`（Knuth 算法）；
- 权重是 `(种子, 轮次, 住户号)` 的确定性函数（BLAKE2b 取 64 位 → SplitMix64），
  因此：
  - **同户在两表共用同一权重**；
  - 其他住户的新增、删除、重排都**不会改变该户的权重**（权重不依赖行序或邻户）；
  - 重复运行结果逐位可复现；
- 每轮先按桶汇总再计算
  `d_r = 更正加权均分_r − 原表加权均分_r = Σw·s/Σw（更正） − Σw·s/Σw（原）`，
  任一侧 `Σw = 0` 时该轮跳过。

## 存储与事务设计

- 每次更正只重算**该户**的 1000 个轮次贡献（`UPDATE ... ±`），其余户数据不读取；
- 更正表明细与 `corr_rounds` 等汇总在**同一个 SQLite 事务**内提交，任何失败都
  回滚，页面继续展示上一版结果并提示原因；
- 方向切换的事务只包含汇总表语句，明细快照在切换前后逐字节不变（有测试守护）；
- 分析查询仅访问汇总表、`batch_summary` 与 `meta`，满足「分析页只读汇总」；
- 单户更正 / 查询仅访问目标户行与必要的批次方向标量。

```bash

```

覆盖：两列 / 三列 CSV 解析与拒收、权重确定性与「邻户增删不影响本户」、
Pois(1) 经验分布、分位插值、汇总与逐户重算一致（含翻转 + 人工 + 补录 +

零权重轮跳过、空表原因提示、v1 旧库迁移（含旧人工分与移除状态）、
完整 Flask 上传 / 切换 / 更正 / 查询 / 重置流程。
